# Лабораторная работа №4. Управление состоянием в React-приложении

Ветка репозитория: `24`

Клиентская часть курсового проекта **«Платформа для продажи и обмена подержанными вещами с чатом между пользователями»**: приложение «Барахолка» для ведения списка объявлений. Приложение автономное и хранит данные в `localStorage`. В лабораторной работе №5 хранение будет заменено на обращения к REST API из папки репозитория выше.

## Стек

- React 19 (функциональные компоненты, хуки `useState`, `useEffect`, `useMemo`)
- Vite
- localStorage для хранения данных
- Обычный CSS (`App.css`)

## Возможности

- Просмотр списка объявлений: фото (или заглушка), название, цена в белорусских рублях (Br), категория.
- Добавление объявления через управляемую форму с проверкой обязательных полей.
- Выбор категории из фиксированного списка.
- Редактирование (кнопка «Изменить» подставляет данные в форму) и удаление объявлений.
- Поиск по названию без учёта регистра.
- Фильтрация по категории и диапазону цены.
- Сортировка: сначала новые, сначала старые, цена по возрастанию, цена по убыванию.
- Статистика: количество показанных объявлений из общего числа и их суммарная стоимость.
- Сохранение данных в `localStorage` и восстановление после перезагрузки страницы.

## Соответствие требованиям лабораторной работы

| Требование | Где реализовано |
|---|---|
| `useState` для массива данных и полей ввода | `ListingList.jsx`, `ListingForm.jsx` |
| Сохранение списка в localStorage при каждом изменении | `hooks/useLocalStorage.js`, `useEffect` с зависимостями `[key, value]` |
| Загрузка данных из localStorage при монтировании | `hooks/useLocalStorage.js`, функция-инициализатор `useState` с `try/catch` |
| Инициализация начальными данными при пустом хранилище | `initialListings` в `ListingList.jsx` |
| Добавление, удаление, редактирование | `saveListing`, `removeListing`, `startEdit` в `ListingList.jsx` |
| Фильтрация и сортировка | `useMemo` в `ListingList.jsx`, панель `ListingFilters.jsx` |
| Изменение `document.title` | `useEffect` в `ListingList.jsx` (количество объявлений) |
| Имитация загрузки с сервера (1 с) | `useEffect` + `setTimeout` с очисткой в `ListingList.jsx` |
| Автосохранение с debounce 500 мс | `useEffect` + `setTimeout` с очисткой в `ListingForm.jsx` (черновик формы) |
| Подсчёт статистики | `useMemo` (`totalSum`) и строка «Показано: N из M» в `ListingList.jsx` |
| Логика localStorage в отдельном хуке | `hooks/useLocalStorage.js` |

## Запуск

Из корня репозитория:

```bash
cd client
npm install --legacy-peer-deps
npm run dev
```

Приложение откроется по адресу http://localhost:5173/

Сборка для продакшена:

```bash
npm run build
```

> Флаг `--legacy-peer-deps` нужен из-за ошибки менеджера пакетов npm 10 (`Cannot read properties of null (reading 'edgesOut')`) при разборе необязательных зависимостей.

## Данные в localStorage

| Ключ | Содержимое |
|---|---|
| `listings` | массив объявлений в формате JSON: `id`, `title`, `category`, `price`, `image` |
| `listingDraft` | черновик формы добавления (сохраняется с задержкой 500 мс после ввода) |

Чтобы сбросить приложение к начальному состоянию, удалите оба ключа в DevTools → Application → Local Storage и обновите страницу.

## Проверка

1. Запустить `npm run dev`, открыть приложение в Google Chrome.
2. Добавить объявление, отредактировать его, удалить.
3. Проверить поиск, фильтр по категории и цене, сортировку.
4. Обновить страницу (Cmd+R): список должен сохраниться.
5. В DevTools → Application → Local Storage убедиться, что ключ `listings` содержит корректный JSON.
